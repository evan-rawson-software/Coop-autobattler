# Assets

Pixel-art sprites for the game. Everything here is **original work generated by
the repository's own script** (`packages/art`, run with `pnpm art:build`). No
third-party assets are included, so there is nothing to credit. The repository
does not have a licence file yet; the sprites are covered by the repository's
licence terms once the owner adds one.

```
assets/
  sprites/
    atlas.json    name -> region, frame count, fps, anchor; palette; tint ramps; autotile masks
    tiles.png     terrain, resource nodes and conduits on an exact 16 px grid (no gutter)
    buildings.png buildings, tier trims and pips
    units.png     units, three versions each (neutral, side A, side B)
    effects.png   hit spark, explosion, spawn puff, turret shot, shadow
    ui.png        panel and page textures, 9-slices, icons
```

The PNGs and `atlas.json` are committed. A test (`packages/art`) rebuilds them
in memory and fails if the committed sheets differ in size or in any decoded
pixel, or if `atlas.json` differs in value, so the script and the files never
drift. The test compares pixels, not file bytes, because the bytes of a
compressed PNG depend on the zlib build inside Node.

## Regenerating

```
pnpm art:build     # rewrites assets/sprites/*
pnpm --filter @game/art test
```

The pixels are deterministic: fixed seeds, no clock, and no sine, cosine,
arctangent, power or hypot calls in generation code (angles come from constant
tables in `packages/art/src/trig.ts`), so no JavaScript engine can produce
different pixels. To change a sprite edit the matching file under
`packages/art/src/sprites/` and rebuild. Review the result on the `#sprites`
page of the web build (`pnpm --filter @game/web dev`, then open `#sprites`).

## Style

- Top-down, 16x16 base tile, light from the top-left, 1-px dark outline on
  buildings and units, nearest-neighbour scaling only.
- Buildings fill whole tiles that match `footprint` in `content/buildings.json`
  (1x1 is 16x16, 2x2 is 32x32). A test checks this.
- Units are 16x16, top-down figures with a head and shoulders. The BODY (tunic,
  cloak, hood, shield face, drone hull) carries the team colour. Side A faces
  north (up the screen) and wears a gold plume (a fan standing in front of the
  head or hull); side B faces south and has bone horns (or wedges on the drone),
  so the sides differ in silhouette as well as in colour. `fx_shadow` is a soft
  shadow to place under flyers.
- Tiers: a tier 2 building gets silver corner brackets (`tier_trim_*`), tier 3
  gold ones, plus the pips (`tier_pips`).
- A restrained shared palette on a dark UI. It is listed in `atlas.json`
  (`palette`, 32 colours, plus the tint ramp described below).

## Atlas format

`atlas.json`:

```jsonc
{
  "version": 1,
  "tile": 16,
  "gutter": 1,                      // empty pixels between sprites on free-form sheets
  "filter": "nearest",
  "sheets": {
    "tiles": { "file": "tiles.png", "w": 320, "h": 176, "grid": 16 },   // "grid": every sprite is on this grid, no gutter
    "units": { "file": "units.png", "w": 320, "h": 236 }, ...
  },
  "autotile": { "blob47": { "bits": { "N": 1, "NE": 2, ... }, "masks": [0, 1, ...] } },
  "palette": [{ "key": "K", "name": "ink", "hex": "#0a0d11" }, ...],
  "tint": {
    "keys": ["X", "x", "Z"],
    "neutral": ["#6e6e6e", "#a6a6a6", "#dcdcdc"],   // the swappable greys
    "teamA": ["#1f4f9e", "#3f86e0", "#9cc8ff"],     // dark, mid, light
    "teamB": ["#9e3a14", "#e0742a", "#ffc48a"],
    "resources": { "res_a": ["#...", "#...", "#..."], ... }  // from content/resources.json
  },
  "sprites": {
    "unit_soldier@a.walk": {
      "sheet": "units", "x": 0, "y": 0,
      "w": 16, "h": 16,              // size of ONE frame
      "frames": 2,                   // frame i is at x + (i % columns) * w, y + floor(i / columns) * h
      "columns": 8,                  // optional: frames per row (default: all in one row)
      "autotile": "blob47",          // optional: frames follow the autotile scheme below
      "fps": 6,                      // 0 = static (or a set of variants, e.g. autotile)
      "anchor": [8, 8],              // pixel inside a frame that sits on the object's centre
      "category": "unit",
      "id": "unit_soldier",          // content id when the sprite stands for one
      "planned": true,               // placeholder for content that does not exist yet
      "nineSlice": [5, 5, 5, 5],     // left, top, right, bottom margins, for UI frames
      "tintable": true,              // uses the tint keys, see below
      "note": "..."
    }
  },
  "planned": ["unit_archer", "unit_drone", "bld_range", "bld_hangar"]   // content ids
}
```

A region is `x, y, w * columns, h * rows` (rows = ceil(frames / columns)).
Regions never overlap and always lie inside their sheet (tested).

`planned` lists the content ids that have art but are not in content yet. It is
derived: an id is planned only while it is missing from `content/`, so adding a
planned unit or building to content removes the flag by itself (tested).

## Naming

| Pattern                    | Meaning                                                              |
| -------------------------- | -------------------------------------------------------------------- |
| `bld_<id>`                 | A building, named by its content id. `bld_turret_base` and `bld_turret_head` split the turret so the head can rotate (anchor on the pivot, barrel points north). |
| `tier_pips`                | Overlay, frame 0 to 2 = tier 1 to 3. Draw on the bottom-left tile of a building. |
| `tier_trim_1x1`, `tier_trim_2x2` | Overlay for a whole building: frame 0 = tier 2 (silver corner brackets), frame 1 = tier 3 (gold). Tier 1 has none. |
| `unit_<id>`                | Neutral unit, idle (1 frame). `.walk` is 2 frames, `.attack` 2 frames (wind-up, strike). |
| `unit_<id>@a`, `@b`        | Same, pre-tinted for side A (faces north) and side B (faces south).  |
| `ter_lake`, `ter_cliff`    | Terrain ids. `ter_lake_auto` and `ter_cliff_auto` are 47-frame autotile sets, see below. Draw over ground. |
| `ground_1..6`, `neutral_1..4` | Seamless buildable and neutral-zone ground. Pick a variant at random per cell. |
| `node_<res id>`            | Resource node, pre-tinted from the resource colour; each resource has its own shape. |
| `conduit_straight`, `_corner`, `_t`, `_cross`, `_end`, `conduit_item` | Neutral conduits. Open sides: straight N+S, corner N+E, t E+S+W, cross all, end S only. Rotate by quarter turns for the other orientations. |
| `fx_*`                     | Effects: `fx_hit_spark` (3 frames), `fx_explosion` (4 frames, 32x32), `fx_spawn_puff` (3), `fx_turret_shot` (points north), `fx_shadow`. |
| `ui_*`                     | `ui_panel` (32x32) and `ui_bg` (64x64) tileable, `ui_button_normal/hover/disabled`, `ui_card` (9-slice), `ui_icon_coin/heart/lock/ready`, `ui_event_<type>` for each event type in `content/events.json`. |

Planned content (`unit_archer`, `unit_drone`, `bld_range`, `bld_hangar`) has
sprites already and is listed under `planned` in the atlas.

## Autotiles (lake and cliff)

`ter_lake_auto` and `ter_cliff_auto` have 47 frames laid out 8 per row (the
sprite has `"columns": 8`). Frame `i` shows one neighbour pattern:

| Bit value | 1 | 2  | 4 | 8  | 16 | 32 | 64 | 128 |
| --------- | - | -- | - | -- | -- | -- | -- | --- |
| Neighbour | N | NE | E | SE | S  | SW | W  | NW  |

For a cell, add the bit of every neighbour that is the same terrain. A corner
bit (NE, SE, SW, NW) only counts when both of its side neighbours are present,
so clear it otherwise. That leaves 47 distinct masks; `atlas.autotile.blob47.masks`
lists them in ascending order and the frame index is the position of the cell's
mask in that list (mask 0 is frame 0, mask 255 is frame 46).

- Side absent: that edge is drawn (shoreline, or cliff lip and face).
- Two adjacent sides absent: rounded outer corner.
- Both sides present, corner absent: concave inner corner (the notch).

The cliff is a raised slab: a light top with a bright lip on its north and west
edges, and a dark three-pixel south face wherever the south side is open.

## Tiles sheet and Godot TileSet

`tiles.png` holds the terrain, the resource nodes and the conduits, on an exact
16 px grid with **no gutter and no margin**. Every region starts on a multiple of
16 and is a whole number of cells, so one `TileSetAtlasSource` covers the whole
sheet. All other sheets are free-form (1 px gutter) and are used as atlas
regions, not as a grid.

TileSet settings:

- `TileSet.tile_size = Vector2i(16, 16)`
- one `TileSetAtlasSource`: `texture = tiles.png`, `texture_region_size =
  Vector2i(16, 16)`, `margins = Vector2i(0, 0)`, `separation = Vector2i(0, 0)`.
  Leave `use_texture_padding` on (the default): Godot then pads each tile at
  load time, so there is no bleeding at fractional zoom even without a gutter
  in the file.
- Add tiles from the atlas: for each sprite on the `tiles` sheet and each frame
  `i`, the cell is `Vector2i(x / 16 + i % columns, y / 16 + i / columns)`
  (`columns` defaults to `frames`).
- Animated tiles (`ter_lake`, `node_*`, 2 frames): create the tile at the first
  cell, set `animation_frames_count` to `frames` and `animation_speed` to `fps`.
  With `animation_columns` left at 0 the frames are read as one horizontal line,
  which is how they are stored.
- Ground and neutral variants: add each as its own tile and set
  `TileData.probability` so a random one is placed per cell.
- Autotiles: use a terrain set in "Match Corners and Sides" mode. For frame `i`
  with mask `m = masks[i]`, set the peering bit to terrain 0 where the bit is set
  and to -1 where it is not:

  | Bit  | `TileSet.CellNeighbor`        |
  | ---- | ----------------------------- |
  | N    | `CELL_NEIGHBOR_TOP_SIDE`      |
  | NE   | `CELL_NEIGHBOR_TOP_RIGHT_CORNER` |
  | E    | `CELL_NEIGHBOR_RIGHT_SIDE`    |
  | SE   | `CELL_NEIGHBOR_BOTTOM_RIGHT_CORNER` |
  | S    | `CELL_NEIGHBOR_BOTTOM_SIDE`   |
  | SW   | `CELL_NEIGHBOR_BOTTOM_LEFT_CORNER` |
  | W    | `CELL_NEIGHBOR_LEFT_SIDE`     |
  | NW   | `CELL_NEIGHBOR_TOP_LEFT_CORNER` |

- Conduits: add the five pieces once and enable the `TileData` transpose and flip
  alternatives for the other orientations; tint them with the shader below or
  with a modulate for a plain overall tint.

## Tinting

Parts that take a runtime colour use three pure greys (`tint.neutral`). They
are the only pure greys in any sprite, so swapping exactly those three colours
for another dark/mid/light ramp recolours the sprite cleanly. Sprites with
`"tintable": true` are drawn this way: neutral units (team colour) and the
conduit pieces (resource colour, `tint.resources`). For units the two sides are
also provided pre-tinted (`@a`, `@b`), which is simpler where a palette swap is
awkward, and the pre-tinted and draw-time-tinted versions agree on the body
pixels (tested). Resource nodes are pre-tinted only.

## Importing into Godot 4

1. Copy `assets/sprites/` into the project. In the Import dock keep
   **Compress > Mode: Lossless** and mipmaps off. Godot 4 has no "Filter" import
   option; filtering is set where the texture is drawn (next step).
2. Filtering: set `CanvasItem.texture_filter = Nearest` on the nodes that draw
   sprites, or once for the whole project under Project Settings > Rendering >
   Textures > Canvas Textures > Default Texture Filter = Nearest. Use integer
   scales and, for a pixel-perfect look, Project Settings > Display > Window >
   Stretch mode `canvas_items` with a snapped scale.
3. Static sprite: an `AtlasTexture` with the sheet as `atlas` and
   `region = Rect2(x, y, w, h)` from the atlas entry.
4. Animation: for each sprite with `frames > 1`, add an animation to a
   `SpriteFrames` resource with `fps` from the atlas (loop on for walk and idle,
   off for effects). Frame `i` is an `AtlasTexture` with
   `region = Rect2(x + (i % columns) * w, y + (i / columns) * h, w, h)`. Sprites
   on the `tiles` sheet go in a `TileSet` instead, see above.
5. Positioning: put the node's origin at the atlas `anchor` (set
   `Sprite2D.offset = -Vector2(anchor)` with `centered = false`).
6. 9-slices (`nineSlice`): use a `NinePatchRect` with the region as
   `region_rect` and `patch_margin_left/top/right/bottom` from the margins.
7. Team and resource colours, two options:
   - **Pre-tinted sprites.** Use `unit_<id>@a` and `unit_<id>@b`. Nothing else
     to set up. Resource nodes are always pre-tinted.
   - **Palette-swap shader** on the neutral sprite, keyed on the three greys.
     `modulate` is not a substitute: it multiplies every pixel by the colour, so
     the three greys become darker versions of the tint but steel, gold and
     outlines are tinted as well, and nothing maps to the exact team ramp. Use
     `modulate` only for an overall effect such as a damage flash or fading
     `fx_shadow`.

   ```glsl
   shader_type canvas_item;

   // The three swappable greys from atlas.json tint.neutral, as 0..255.
   const float G_DARK = 110.0;   // #6e6e6e
   const float G_MID = 166.0;    // #a6a6a6
   const float G_LIGHT = 220.0;  // #dcdcdc

   uniform vec4 ramp_dark : source_color = vec4(0.122, 0.310, 0.620, 1.0);
   uniform vec4 ramp_mid : source_color = vec4(0.247, 0.525, 0.878, 1.0);
   uniform vec4 ramp_light : source_color = vec4(0.612, 0.784, 1.0, 1.0);

   bool is_grey(vec3 rgb, float level) {
   	return all(lessThan(abs(rgb * 255.0 - vec3(level)), vec3(0.5)));
   }

   void fragment() {
   	vec4 c = texture(TEXTURE, UV);
   	if (c.a > 0.0) {
   		if (is_grey(c.rgb, G_DARK)) c.rgb = ramp_dark.rgb;
   		else if (is_grey(c.rgb, G_MID)) c.rgb = ramp_mid.rgb;
   		else if (is_grey(c.rgb, G_LIGHT)) c.rgb = ramp_light.rgb;
   	}
   	COLOR = c;
   }
   ```

   Needs nearest filtering (step 2) so the greys are sampled exactly. Set the
   three uniforms per node (`material.set_shader_parameter("ramp_mid", ...)`)
   from `tint.teamA`, `tint.teamB` or `tint.resources`.
8. Flyers: place `fx_shadow` under the unit and scale it with the unit.
